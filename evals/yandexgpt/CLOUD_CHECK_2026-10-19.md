# Проверка доступа к Yandex Cloud — 19.10.2026

Этот файл сохраняет результаты исходной версии v1. Найденные здесь ошибки затем исправлены и повторно проверены: [протокол v2](SEMANTIC_REGRESSION_2026-10-19.md). Исторические суммы ниже относятся только к первому прогону.

Пользователь прямо разрешил использовать существующий доступ FlowInvoice для настройки Fixit. В локальной конфигурации FlowInvoice найдены существующие ключ и каталог AI Studio. Они использованы для отдельного игнорируемого файла Fixit `.env.yandex.local` с правами `0600`. Значения не выводились и не добавлялись в Git. Исходная конфигурация FlowInvoice, IAM, ключи и облачная инфраструктура не изменялись. Существующий ключ остаётся общим: независимое отключение/ротация доступа Fixit потребует отдельного решения.

Это проверка API для AI-00. Приложение Fixit и production пока не используют AI; `paid_calls_enabled=false` для приложения сохранён. Явно запущенный диагностический CLI имеет отдельное назначение и выполняет только ограниченную синтетическую проверку.

## Подтверждено реальными запросами

- Работает аутентификация к `https://ai.api.cloud.yandex.net/v1/chat/completions`.
- Каталогу доступны явные модели `yandexgpt-5.1` и `yandexgpt-5-pro`.
- Проверен `response_format=json_schema`, локальная валидация обязательных полей и типов. Все 7 полученных ответов прошли JSON-проверку; ссылки в фактах историй содержали переданные ID.
- В каждый запрос передавался `x-data-logging-enabled:false`. Аккаунтные настройки трейсов, хранение и индивидуальные квоты не проверялись; отправленный заголовок не является подтверждением полного отключения хранения.
- Отправлялись только синтетические tune-примеры, сценарный промпт и JSON-схема. Эталонные факты и формулировки не отправлялись.

## Предварительный просмотр качества

Это просмотр агентом небольшой tune-выборки, не профильная приёмка и не контрольная оценка holdout.

- **H001, обе модели:** в резюме появилось «проблема не устранена». История подтверждает новую жалобу после замены уплотнения, но не доказывает непрерывную неисправность или неуспех самой предыдущей работы. Требуется более точная формулировка с датами и сохранением источника жалобы. Одна лишь валидная JSON-схема не предотвращает такой вывод.
- **H026, Pro 5.1:** факты правильно сохраняют отсутствие проверки, но summary сводится к названию оборудования; недостаточно полезно.
- **R011:** обе модели сохранили ожидание детали и не придумали замену; Pro 5 отнёс заказ втулки в work. Для UI стоит явно разделять ремонтные действия и организационный комментарий.
- **R001, Pro 5:** сохранены жалоба, прочистка фильтра и восстановление подачи. Сравнимого успешного ответа Pro 5.1 здесь пока нет.

Модель для продукта **не выбрана**. Следующий технический шаг — уточнить сценарные промпты/схемы на tune, отдельно ограничить выводы в summary и повторить нужные случаи как новые явно учтённые версии. Holdout пока не использовался. Профильная оценка и реальные замеры всё ещё требуются для завершения AI-00.

## Инструмент и границы бюджета

Добавлен `scripts/ai_cloud_check.py`. Он не читает бизнес-БД, разрешает только четыре заданных синтетических tune ID, использует фиксированный HTTPS endpoint, запрещает redirects и работает последовательно. Секреты/сырые исключения провайдера не печатает. Флаг `--run` обязателен. Локальный JSON-журнал и результаты имеют права `0600` и исключены из Git.

Одна файловая блокировка удерживается на время последовательного прогона. До вызова сохраняется резерв, после usage — оценка расхода; неопределённые попытки удерживают резерв. Повторный запуск не вызывает снова уже записанные операции. Учитываются общие пределы 300 ₽/месяц, 10 ₽/день и 30 ₽ на первичную оценку, все в рамках одного бюджета Fixit.

Расчёт резерва консервативный: байты UTF-8 запроса как входные токены плюс 1024 токена запаса и максимальный выход 512 токенов. Это локальная оценка по опубликованному тарифу, не лимит биллинга Yandex Cloud и не доказанная граница внутреннего токенизатора. Расходы FlowInvoice и любых других клиентов общего ключа в этот журнал не входят. Этот CLI не заменяет PostgreSQL-учёт и контроль расходов будущего серверного AI-01. Параллельные вызовы приложения пока отсутствуют.

Команды из корня Fixit:

```sh
# Без сети и расходов
python3 -m unittest discover -s tests -p 'test_ai_*.py' -v

# Явный платный диагностический запуск; записанные операции будут пропущены
python3 -m scripts.ai_cloud_check --run
```

Проверки: **18 unittest прошли** (11 подготовки и 7 облачного CLI), включая сохранение резерва, каждый лимит, дубли операций, типы ответа и права файла журнала. Настоящие API-запросы описаны отдельно выше; unittest не выдаются за их замену. Полный suite приложения не запускался: runtime приложения не менялся.
